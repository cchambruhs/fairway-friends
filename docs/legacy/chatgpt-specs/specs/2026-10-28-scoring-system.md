# Approved scoring implementation specification

The user's explicit implementation request supersedes the earlier proposed beaten/tied formula. Implement the exact fixed-placement default (25,20,16,13,11,10,9,8,7,6; decrement thereafter to minimum 1) and field-size formula 25*(N-placement)/(N-1), singleton 25. Rank completed league participants by strokes. Ties share points of occupied positions; calculate using unrounded formula values, then round final round points to two decimals.

Only leader-approved complete scorecards count. Members submit imported cards into one of their leagues; leader reviews. Preserve canonical round deduplication. Add reusable league creation, invite links, memberships, start, review, completion, and automatic standings so scoring is usable end to end. Preserve public access, existing stats and gear. All mutations enforce authenticated membership/leadership on the server.

Leader configures scoring while draft: optional best N round limit (0 means all), number of lowest rounds dropped, participation/birdie/ace bonuses (off by default, configurable nonnegative points), championship multiplier (default 1), and championship designation during approval. Championship designations must be explicit and visible in review/results; multiplier amount is locked at Start. Round points = (split placement points + enabled score-derived bonuses)*championship multiplier, rounded to cents. Count highest results after dropping D lowest; apply best N cap if nonzero. Wins, seconds, and average finishing position use counted results only; a tie spanning positions uses midrank for average, ties at first count as wins and ties at second count as seconds. Equal season points compare wins descending, seconds descending, average midrank ascending, then share rank with Playoff required. Leader records an explicit playoff order at finalization for otherwise tied groups; no hidden alphabetical winner. Standings include zero-round members after players with counted rounds; no spurious playoff flag for inactive players.

Cards on a league are one competition; nonmembers excluded. Single-player complete league cards allowed (latest request explicitly defines singleton scoring). A card with an incomplete league participant cannot be approved until refreshed complete. Course/layout and season bounds apply. Date comparisons use explicit league timezone (America/Chicago default) for local UDisc timestamps; preserve start-button timestamp and show round eligibility rule. End date blocks new submissions, but pending nominations can be resolved before completion. No score mutation from league actions. Approved cards use review-time score snapshots; refresh changes require re-review and remove provisional points meanwhile. Completed league standings/payouts are immutable snapshots. Concurrency uses compare-and-swap revisioned league state, with memberships, nominations and settings in a single stored aggregate for transactional consistency. Public responses remove account IDs, invite tokens, and private review submissions.

Include league creation preview for both systems using sample stroke inputs, showing ties and singleton behavior. Show rules lock status, round-level base/bonus/multiplier totals, counted/dropped flags, cumulative totals, rank and tiebreak detail. Player dashboards gain a League tab and personal dashboard navigation. Invitation joining persists through sign-in.

Retain previously requested payout choices: fixed amounts by place (tied places split occupied pots) or proportional point shares of cash pool. Reconcile integer cents by largest remainders; zero total points leaves cash unallocated. Declare funds and record payouts; no payment processing. Freeze payout settings at Start. Include setup duration, prize notes and buy-in. Avatar/history import will be handled as subsequent tasks within this session, using the earlier design.

Default decisions above are implementation choices made to fulfill unspecified options; expose them in the UI and user handoff.
